# Глоссарий и бизнес-правила (domain.md)

Единый источник правды по бизнес-сущностям, жизненному циклу сделки,
формулам метрик и правилам представления данных на дашборде.

---

## Базовые сущности

### Manager

Менеджер отдела продаж — субъект, чья результативность оценивается дашбордом.

| Атрибут | Тип | Описание |
|---|---|---|
| `id` | ID | Уникальный идентификатор. |
| `name` | string | Полное имя менеджера. |
| `team` | string | Команда (группировка/фильтрация). |
| `position` | string | Должность (группировка/фильтрация). |
| `active` | boolean | Признак активности. |
| `avatar` | string \| null | Ссылка/данные аватара (если задан). |
| `initials` | string | Инициалы. |

Связи: автор множества `Sale`.

### Customer

Клиент — покупатель товаров.

| Атрибут | Тип | Описание |
|---|---|---|
| `id` | ID | Уникальный идентификатор. |
| `name` | string | Название клиента. |
| `company` | string | Компания. |
| `segment` | enum | Сегмент клиента — см. «Сегменты клиентов». |
| `since` | год | Год начала работы с клиентом. |

Связи: участвует во множестве `Sale`.

### Сегменты клиентов

`Customer.segment` — сегмент клиента **по размеру** (реалистично для B2B-продаж и согласуется с разбросом чеков в seed).

| Значение (enum) | Подпись в UI | Описание | Профиль покупок |
|---|---|---|---|
| `Enterprise` | Крупный бизнес | Крупные компании, гос/корпорации | Редкие, очень крупные сделки; высокий средний чек |
| `Mid-market` | Средний бизнес | Средний бизнес | Умеренный чек, регулярные закупки |
| `SMB` | Малый бизнес | Малый и средний бизнес (small and medium business), розничные партнёры | Частые мелкие сделки; низкий средний чек |

**Назначение.** В seed — источник разброса средних чеков и сумм сделок. В
аналитике — дополнительный разрез (Revenue/GP и средний чек по сегментам).

### Category

Категория товаров — верхний уровень товарной классификации.

| Атрибут | Тип | Описание |
|---|---|---|
| `id` | ID | Уникальный идентификатор. |
| `name` | string | Название категории. |

Связи: содержит множество `Product`.

### Product

Товар — позиция каталога, участвующая в продажах.

| Атрибут | Тип | Описание |
|---|---|---|
| `id` | ID | Уникальный идентификатор. |
| `name` | string | Маркетинговое название товара. |
| `sku` | string | Артикул (Stock Keeping Unit). Уникален, отличает комплектации с близким `name`. |
| `categoryId` | ID → Category | Принадлежность категории. |
| `price` | money | Текущая цена продажи (прайс каталога). |
| `cost` | money | Текущая закупочная цена (себестоимость). |

**Роль справочных цен.** `Product.price`/`cost` — *текущие* значения каталога,
они **не участвуют** в расчёте метрик: метрики считаются исключительно из
замороженных `SaleItem.salePrice`/`unitCost`. Справочник нужен для реалистичного
seed и как опциональная характеристика товара.

Связи: входит в `SaleItem` (многие ко многим с `Sale` через позиции).

### Sale

Продажа — головной документ сделки. Единица подсчёта `count(Sale)` и Average Check.

Сделка моделируется **датами событий**, а не статусом: каждое свершившееся событие
имеет свою дату и не переписывается. Статус — производная величина.

| Атрибут | Тип | Описание |
|---|---|---|
| `id` | ID | Уникальный идентификатор. |
| `managerId` | ID → Manager | Ответственный менеджер. |
| `customerId` | ID → Customer | Покупатель. |
| `createdAt` | datetime | Дата, когда менеджер завёл сделку. |
| `paidAt` | datetime \| null | Дата оплаты заказа. |
| `refundedAt` | datetime \| null | Дата возврата заказа. |
| `cancelledAt` | datetime \| null | Дата отмены заказа. |
| `status` | enum (производный) | `Paid` / `Refunded` / `Cancelled` — выводится из дат, см. «Жизненный цикл сделки». |

Связи: содержит список `SaleItem` (1:N).

### SaleItem

Позиция продажи — атомарная единица суммирования всех денежных метрик.

| Атрибут | Тип | Описание |
|---|---|---|
| `id` | ID | Уникальный идентификатор позиции. |
| `saleId` | ID → Sale | Принадлежность продаже. |
| `productId` | ID → Product | Товар. |
| `quantity` | number | Количество единиц. |
| `salePrice` | money | Цена продажи за единицу (компонент Revenue). |
| `unitCost` | money | Себестоимость единицы (компонент Cost). |

## Жизненный цикл сделки

### Цепочка событий

```
createdAt → paidAt → refundedAt
   └────────→ cancelledAt
```

### Допустимые комбинации дат и статус

| Состояние | `createdAt` | `paidAt` | `refundedAt` | `cancelledAt` | `status` | Смысл |
|---|---|---|---|---|---|---|
| Оплачена | есть | есть | нет | нет | `Paid` | Деньги получены и остались у компании. |
| Возвращена | есть | есть | есть | нет | `Refunded` | Оплата была, деньги возвращены клиенту. |
| Отменена | есть | нет | нет | есть | `Cancelled` | Сделка не состоялась, оплаты не было. |

Порядок дат: `createdAt ≤ paidAt ≤ refundedAt` и `createdAt ≤ cancelledAt`.

## Принципы расчёта метрик

### Роли дат

Один факт `Sale` несёт несколько дат, и каждая метрика выбирает **свою** — по
тому, на какой вопрос она отвечает. Числитель и знаменатель одной метрики всегда
берут **одну** дату.

| Дата | Роль в метриках |
|---|---|
| `createdAt` | Ни в одну метрику не входит: фиксирует, когда менеджер завёл сделку, служит базой порядка для остальных дат. |
| `paidAt` | **Когорта оплаты** — основа для Revenue, Cost, GP, Margin, Average Check, Sales Count, Refund Rate; часть знаменателя Cancellation Rate. |
| `refundedAt` | **Событие возврата** — сумма и количество возвратов (блок «Потери»). |
| `cancelledAt` | **Событие отмены** — числитель и вторая часть знаменателя Cancellation Rate; сумма и количество отмен (блок «Потери»). |

### Когорта и событие

Структура данных определяет, какая метрика считается когортной, а какая —
событийной. Это не произвол, а следствие взаимоотношений исходов сделки.

**Возврат накладывается на оплату** (оплаченный заказ остаётся оплаченным), поэтому
корректного событийного знаменателя у доли возвратов нет — она **когортная**:
и числитель, и знаменатель отбираются по `paidAt` («какая доля оплаченных в периоде
заказов в итоге вернулась»). Возвраты по `refundedAt` приходят в том числе по
заказам прошлых периодов, и делить их на оплаты текущего нельзя — числитель и
знаменатель окажутся из разных выборок.

**Отмена исключает оплату** (исходы взаимоисключающи и исчерпывающи), поэтому
знаменатель по событиям существует — доля отмен **событийная**. Отмена — исход, а
не наложение на оплату, поэтому у доли отмен есть корректный знаменатель по дате
события, и история периода заморожена — задним числом значения не меняются.

### Признание результата и потери

**Признание результата (Revenue, GP, Margin, Average Check, Sales Count) — по
когорте оплаты `paidAt`.** Заказ, оплаченный в мае и возвращённый в июне, не входит
в выручку мая. Это **net по когорте**: возврат вычитается из периода заказа, а не
переносится в период возврата. Так числитель и знаменатель остаются в одной
когорте, а Gross Profit не содержит прибыли по возвращённым сделкам.

**Потери (возвраты и отмены) — по дате события (`refundedAt` / `cancelledAt`).**
Сумма и количество потерь относятся к периоду, когда событие произошло: возврат
заказа, оплаченного в мае и возвращённого в июне, виден в июне — там, где наступил
`refundedAt`. Эти величины **событийные и заморожены** — по прошедшим периодам
новые события не поступают.

Следствие: у одного периода две независимые картины — «сколько заработали»
(когорта оплаты) и «сколько и когда потеряли» (события потерь). Они не смешиваются.

### Дозревание когорты

Возвраты приходят с задержкой, поэтому чем ближе период к текущей дате, тем
выше вероятность, что доля возвратов ещё изменится. Бизнесу нужно учитывать, что
значения последних периодов не окончательны. Сумма и количество возвратов
(`refundedAt`) от этого не зависят — они событийные и заморожены.

## Недостаточность данных

Значение не выводится, если данных недостаточно для корректного расчёта или
сравнения:

| Условие | Результат | Где применяется |
|---|---|---|
| Знаменатель равен нулю | `—` | Margin, Average Check, Refund Rate, Cancellation Rate |
| Размер выборки ниже минимума | `мало данных` | Refund Rate (товар), Cancellation Rate (менеджер) — см. константы `Refund Min Sample`, `Cancellation Min Sample` |
| Базовый период для Δ равен нулю или данных недостаточно | `—` | Δ для всех метрик, включая Refund Rate |

## Метрики

### Обзор

```
Revenue             = Σ ( Quantity × salePrice )                 по paidAt, без возврата
Gross Profit        = Revenue − Cost
Margin              = Gross Profit / Revenue
Average Check       = Revenue / count(Sale)                      по paidAt
Sales Count         = count(Sale)                                по paidAt
Refund Rate         = count(refundedAt) / count(paidAt)          когорта оплаты
Cancellation Rate   = count(cancelledAt) / (count(paidAt) + count(cancelledAt))   по событиям
```

### Revenue — выручка

Базовый объём продаж: показывает масштаб работы и служит денежной базой для всех
относительных расчётов периода.

```
Revenue = Σ (SaleItem.Quantity × SaleItem.salePrice)
          WHERE paidAt ∈ [from, to] AND refundedAt IS NULL
```

Считается по `paidAt` (деньги получены) и исключает заказы, которые **в итоге**
возвращены — это net по когорте (см. «Принципы расчёта метрик»).

### Cost — себестоимость

```
Cost = Σ (SaleItem.Quantity × SaleItem.unitCost)
       WHERE paidAt ∈ [from, to] AND refundedAt IS NULL
```

Считается по той же выборке, что Revenue.

### Gross Profit — валовая прибыль

Абсолютный финансовый результат: сколько реально заработано на продажах. Не
содержит прибыли по возвращённым сделкам, поскольку считается по той же выборке,
что Revenue.

```
Gross Profit = Revenue − Cost
```

### Margin — маржинальность

Доля валовой прибыли в выручке: показывает, насколько выгодно продавать — при
большой выручке можно иметь низкую маржинальность, если себестоимость съедает
почти весь доход. Считается по агрегату периода, **не** как среднее
маржинальностей позиций.

```
Margin = Gross Profit / Revenue   в процентах
```

При нулевой выручке за период неопределена → `—`.

### Average Check — средний чек

Типичный размер сделки. Отвечает на вопрос «на какую сумму в среднем продают за
одну сделку».

```
Average Check = Revenue / count(Sale)
                WHERE paidAt ∈ [from, to]
```

Числитель и знаменатель — по одной когорте `paidAt`. Возвращённые заказы входят в
знаменатель (сделка была оплачена и состоялась), но не в числитель: поэтому
средний чек падает, если по проданному возвращают деньги.

### Sales Count — число продаж

Объём активности: сколько сделок провёл менеджер или подразделение.

```
Sales Count = count(Sale)   WHERE paidAt ∈ [from, to]
```

Оплаченная сделка — состоявшаяся работа с клиентом. Возврат не отменяет этот факт:
возвращённый заказ **остаётся** в Sales Count, потому что оплата была. Отменённая
сделка не входит — оплаты не было.

### Refund Rate — доля возвратов

Показывает, какая часть дошедших до оплаты сделок возвращается. **Метрика
когортная** (см. «Принципы расчёта метрик»).

```
Refund Rate = count(Sale, refundedAt NOT NULL) / count(Sale, paidAt ∈ [from, to])
              в процентах
```

Возврат возможен только по оплаченному заказу, поэтому знаменатель — оплаченные
(`paidAt`), а отменённые (`cancelledAt`) в него не входят.

При нулевом знаменателе доля неопределена → `—`, а не `0%`.

### Cancellation Rate — доля отмен

Показывает, какая часть исходов периода — отмены. Это **не потерянные деньги**, а
неполученная возможность — оплата не проходила ни разу. **Метрика событийная** (см.
«Принципы расчёта метрик»).

```
Cancellation Rate = count(cancelledAt ∈ [from, to])
                    / ( count(paidAt ∈ [from, to]) + count(cancelledAt ∈ [from, to]) )
                    в процентах
```

Знаменатель — **все сделки, разрешившиеся в периоде**: оплаченные и отменённые.
У открытых сделок нет, поэтому исход ровно один и числитель гарантированно входит
в знаменатель.

Числитель доли буквально равен количеству отмен из блока «Потери» (там тоже
`cancelledAt`) — две величины одного блока не расходятся.

При нулевом знаменателе доля неопределена → `—`, а не `0%`.

## Периоды и сравнение

### Активный период

`[from, to)` — полуинтервал, выбранный пользователем или пресетом. **`from`
включается, `to` — нет**: событие на границе `from` входит в период, на границе
`to` — уже нет. Полуинтервал выбран, чтобы активный и предыдущий периоды
примыкали друг к другу без зазора и пересечения (`previous.to == from`).
Все даты — в UTC.

### Предыдущий сопоставимый период

Интервал **той же длительности**, непосредственно предшествующий активному
(конец предыдущего в точности равен началу активного, `previous.to == from`).
Правило одно для всех диапазонов, включая пресеты: `previous = [from − (to − from), from)`.
Пресет задаёт активный период, но не меняет правило вычисления предыдущего:

- `7 дней` → предыдущие 7 дней;
- `Этот месяц` (1–24 сент) → 8–31 августа (те же 24 дня);
- `Прошлый месяц` (сентябрь, 30 дней) → 2–31 августа (те же 30 дней, а не календарный август);
- произвольный диапазон → равное число дней до `from`.

Равная длительность — условие сопоставимости: Δ сравнивает базы одного размера,
а в блоках с дневным разрезом у каждого дня активного периода есть день-пара.

### Изменение к предыдущему периоду (Δ)

```
Δ% = (Meta_current − Meta_prev) / Meta_prev × 100
```

При `Meta_prev = 0` → `—` (не `+∞`).

Направление «хорошо/плохо» зависит от метрики:

| Метрика | Рост означает |
|---|---|
| Revenue, Gross Profit, Margin, Average Check, Sales Count | улучшение |
| Refund Rate | ухудшение |
| Cancellation Rate | ухудшение |

**Один индикатор — одна оценка.** У возвратов и отмен Δ считается по **доле** и в
**процентных пунктах**; сумма и количество цветом не выделяются и своей Δ не имеют
(три раскрашенных величины в одной группе — три вердикта об одном явлении).

Почему п.п., а не %: рост доли с 2,0% до 2,4% в относительных процентах читается как
«+20%», хотя сдвиг ничтожен; `+0,4 п.п.` даёт честную величину.

При пустом знаменателе доли за предыдущий период Δ неопределена → `—`.

Δ доли возвратов не выводится при недостаточности данных (см. «Недостаточность данных»).

## Ранжирование и аналитические разрезы

### Ответственность

- **Cancelled** — персональная ответственность менеджера (потеря клиента), поэтому
  отмены показываются в разрезе менеджеров.
- **Refunds** — ответственность продукта, а не менеджера: менеджер продал то, что продавали. Возвраты анализируются в разрезе **товаров**.

### Рейтинг менеджеров

- Сортировка по активной метрике — **Gross Profit** или **Average Check**, по убыванию.
- **Доля отмен не является метрикой ранжирования** — она контекст строки.
- **При равенстве значений** — детерминированный порядок: сначала по Revenue, затем
  по имени (A→Я). Гарантирует стабильные позиции между перезагрузками.
- **Менеджер без продаж** включается в рейтинг со значениями `0`/`—`, а не скрывается.

### Топы блока потерь

Действуют одинаково для обеих групп, разрез фиксирован: возвраты — товары,
отмены — менеджеры.

- Сортировка по активной метрике (сумма или количество), по убыванию. Доля от итога
  группы — монотонный множитель суммы, поэтому порядок по сумме и по доле совпадает.
- **Вход в список** — любой объект с хотя бы одной потерей; порога доли как условия
  входа нет.
- **При равенстве** — по имени объекта (A→Я).
- **Объект без потерь в список не попадает** (в отличие от рейтинга менеджеров).
- **Инвариант хвоста**: доли строк топа плюс доля «Остальных N» дают 100% группы.

## Константы внимания

Минимальные размеры выборки — бизнес-суждения, поэтому живут здесь, а не в
вёрстке. UI ссылается по имени.

| Константа | Значение | Область применения |
|---|---|---|
| `Refund Min Sample` | 8 продаж | минимум продаж по товару, чтобы доля печаталась |
| `Cancellation Min Sample` | 5 сделок | минимум сделок в знаменателе (`paidAt` или `cancelledAt` в периоде) по менеджеру, чтобы доля печаталась |
| `Dyn Min Base Orders` | 5 заказов | минимум заказов в базовом периоде для «Динамики клиентов» |
| `Dyn Top N` | 5 | размер секций «Рост» / «Падение» в «Динамике клиентов» |

**Минимальная выборка — про статистику, а не про внимание.** Товар, проданный один
раз и возвращённый один раз, даёт долю 100% — это артефакт малой выборки. Ниже
минимума доля не печатается вовсе (`мало данных`), а не печатается без акцента.

## Edge cases → поведение метрик

| Ситуация | Как считаем |
|---|---|
| Cancelled-сделка | Нет `paidAt`, есть `cancelledAt`. Исключена из Revenue/GP/Margin/Sales Count и из знаменателя AC. Входит в числитель и в знаменатель Cancellation Rate (по `cancelledAt`). |
| Refunded-сделка | Есть `paidAt` и `refundedAt`. Исключена из Revenue/Cost/GP/Margin и из числителя AC; входит в знаменатель AC и в Sales Count (по `paidAt`); в числитель Refund Rate и в блок «Потери» (по `refundedAt`). |
| Возврат по заказу прошлого периода | В выручке и AC не появляется нигде (net по когорте заказа). В блоке «Потери» виден в периоде события (`refundedAt`). |
| Возврат по недавнему заказу | Доля возвратов ещё может измениться (возвраты приходят с задержкой). Сумма/количество возвратов событийные и заморожены. |
| Отмена по заказу прошлого периода | Создан в мае, отменён в июне → входит в Cancellation Rate июня (по `cancelledAt`). В мае не оставляет следа: ни в выручке, ни в доле отмен. |
| Отмена — единственный исход периода | Оплат в периоде нет, отмена есть → доля `100%` (знаменатель непустой), сумма и количество отмен показываются. |
| В периоде нет разрешившихся сделок | Ни `paidAt`, ни `cancelledAt`. Cancellation Rate = `—`, Revenue/GP/Sales Count нулевые. |
| Менеджер без продаж | Все метрики `0`/`—`, Δ `—`, в рейтинге с нулями. |
| Менеджер только с отменами | В периоде нет оплат, есть отмены → доля `100%`; если отмен меньше `Cancellation Min Sample` → `мало данных`. |
| Равные значения у двух менеджеров | Детерминированный дополнительный критерий сортировки. |
| Продажа ровно на границе `[from, to)` | На `from` входит в период, на `to` — нет (полуинтервал). |
| Одна очень крупная продажа | Учитывается полностью; Average Check может быть аномально высоким — это корректно по формуле. |
| Разные себестоимости и маржинальность | Margin считается по агрегату периода, не как среднее маржинальностей позиций. |
| Товар в одной продаже несколько раз | Refund Rate(товар) считает продажу один раз. |
| Потери есть, но никто не выделяется | Топ заполнен как обычно. |
| Объектов с потерями меньше топ-N | Показывается сколько есть, без заполнителей; хвост не печатается, если оставлять нечего. |
| Нет ни возвратов, ни отмен | Обе группы: `0 ₽`/`0` и `0,0%` (знаменатель непустой), список заменён на «Возвратов нет» / «Отмен нет». При пустом знаменателе доля — `—`. |
