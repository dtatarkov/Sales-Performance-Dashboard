# Глоссарий и бизнес-правила (terms.md)

Единый источник правды по метрикам и правилам расчёта. Все формулы применяются
**на сервере**; frontend только отображает. Правило по Refund выбирается здесь и
последовательно используется во всей системе (требование секции 3 ТЗ).

---

## Базовые сущности

| Термин | Определение |
|---|---|
| **Manager** | Менеджер отдела продаж: имя, команда/должность, активность, avatar/initials. |
| **Customer** | Клиент: имя, компания, сегмент. |
| **Category** | Категория товаров. |
| **Product** | Товар: название, категория, атрибуты (в т.ч. себестоимость). |
| **Sale** | Продажа: менеджер, клиент, дата, статус. Головной документ сделки. |
| **SaleItem** | Позиция продажи: товар, количество, цена продажи, себестоимость. |

---

## Статусы продажи

| Статус | Значение | Учёт в метриках |
|---|---|---|
| **Paid** | Оплачена | Полный учёт во всех метриках. |
| **Cancelled** | Отменена (не состоялась) | **Исключается** из Revenue, GP, Margin и из «количества продаж». Сделка не считалась состоявшейся. |
| **Refunded** | Возврат | **Исключается** из Revenue и Gross Profit (деньги вернули → прибыли нет). См. «Правило Refund». |

### Правило Refund (выбранная трактовка)
Продажа `Refunded` **не участвует** в выручке, валовой прибыли и маржинальности,
но **учитывается** в «количестве продаж» как отдельный аналитический сигнал
(видно, сколько сделок ушло в возврат). Возвраты выводятся отдельным числом в
KPI/подсказках, чтобы не терять прозрачность.

> Альтернатива (полный учёт до момента возврата) отвергнута: завышала бы
> Revenue исторических периодов. Выбранное правило фиксируется в README.

## Вычисляемые метрики

Суммирование идёт по строкам `SaleItem` только тех продаж, что проходят фильтр
статусов выше.

### Revenue (Выручка)
```
Revenue = Σ ( SaleItem.Quantity × SaleItem.SalePrice )
          по всем Sale со статусом Paid
```
Денежная сумма оплаченных продаж за период.

### Cost (Себестоимость)
```
Cost = Σ ( SaleItem.Quantity × SaleItem.UnitCost )
       по тем же Sale
```
Промежуточная величина для расчёта прибыли.

### Gross Profit (Валовая прибыль)
```
Gross Profit = Revenue − Cost
```
Абсолютная денежная прибыль без накладных расходов. **Основная метрика
результативности менеджера** в рейтинге.

### Margin (Маржинальность)
```
Margin = Gross Profit / Revenue      (выражается в %)
```
Относительная эффективность. При `Revenue = 0` маржа **неопределена** →
отображается как `—`, деления на ноль нет.

### Average Check (Средний чек)
```
Average Check = Revenue / count(Sale)
```
где `count(Sale)` — количество продаж, **включённых в Revenue** (Paid;
Refunded — по выбранному правилу не в выручке, но см. число возвратов отдельно).
При нуле продаж → `—`.

> Важно: знаменатель — число продаж (документов), а не число позиций и не число
> клиентов.

### Sales Count (Количество продаж)
```
Sales Count = count(Sale)  по оплаченным продажам периода
```

## Периоды и сравнение

### Активный период
`[from, to]` — интервал дат, выбранный пользователем (или пресетом).
**Границы включаются**: продажа ровно на `from` или `to` входит в период
(edge case из секции 11). Сравнение по UTC/локальным датам — единый часовой
пояс на всю систему (фиксируется в README).

### Предыдущий сопоставимый период
Берётся интервал **той же длительности**, непосредственно предшествующий
активному:
```
duration   = to − from + 1 день
prevTo     = from − 1 день
prevFrom   = prevTo − duration + 1 день
```
Примеры:
- `7 дней` → предыдущие 7 дней.
- `Этот месяц` (с 1 по 24 сент) → сравнение с **прошлым месяцем** целиком.
- `Прошлый месяц` → месяц перед ним.
- Произвольный диапазон → равное число дней до `from`.

### Изменение к предыдущему периоду (Δ)
```
Δ% = (Мета_current − Meta_prev) / Meta_prev × 100
```
При `Meta_prev = 0` → `—` (не `+∞`). Направление «хорошо/плохо» зависит от
метрики: рост Revenue/GP/Margin/AC — позитивен; рост возвратов — негативен.

## Правила ранжирования (рейтинг менеджеров)

- Сортировка по активной метрике: **Gross Profit** или **Average Check**,
  по убыванию.
- **Тай-брейк при равенстве значений** (edge case «одинаковые результаты»):
  детерминированный порядок — сначала по Revenue, затем по имени менеджера
  (A→Я). Гарантирует стабильность позиций между перезагрузками и отсутствие
  «прыжков» в FLIP-анимации.
- **Менеджер без продаж за период**: включается в рейтинг со значениями `0` /
  `—`, а не скрывается (иначе интерфейс «теряет» людей).
- **Менеджер с единственной крупной продажей**: Average Check может быть
  аномально высоким — это корректно отражается; блок распределения (scatter)
  помогает отличить статистический выброс от регулярной работы.

## Edge cases → поведение метрик (секция 11)

| Ситуация | Как считаем |
|---|---|
| Cancelled-продажа | Исключена из Revenue/GP/Margin/Count. |
| Refunded-продажа | Исключена из Revenue/GP/Margin; показана как «возвраты»; в Count — по выбранному правилу. |
| Менеджер без продаж | Все метрики `0`/`—`, Δ `—`, в рейтинге с нулями. |
| Равные значения у двух менеджеров | Детерминированный тай-брейк (см. выше). |
| Продажа ровно на границе `[from, to]` | Входит в период (границы включаются). |
| Одна очень крупная продажа | Учитывается полностью; видна в distribution/scatter как выброс. |
| Много мелких продаж | Средний чек низкий, Count высокий — корректно. |
| Разные себестоимости и маржа | Margin считается по агрегату периода, не как среднее марж позиций. |

## Соглашения об отображении

- **Деньги**: рубли, компактный формат (`1,2 млн ₽`, `845 тыс ₽`); точное
  значение — в tooltip.
- **Проценты**: один знак после запятой (`37,4%`).
- **Пустые/неопределённые значения**: `—`, а не `0` и не `NaN`.
- **Направление цвета Δ**: зелёный = улучшение метрики, красный = ухудшение
  (с учётом семантики метрики).
