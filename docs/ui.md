# Sales Performance Dashboard — спецификация UI (ui.md)

Desktop-приложение, целевой viewport **1440×900**. Mobile-версия не требуется.
Одна страница — сводный дашборд аналитики продаж менеджеров.

Документ описывает **структуру компонентов верхнего уровня**: что за блок, какие
данные ему нужны, какая логика отображения и какие граничные случаи он обязан
обработать. Формулы и бизнес-правила — в `domain.md`; здесь на них только ссылки.
Документ не фиксирует технические решения: конкретные библиотеки, фреймворки и
способы реализации остаются на усмотрение команды.

**Общее правило.** UI-компоненты не занимаются бизнес-логикой: значения метрик,
Δ, доли и вклады приходят уже вычисленными извне. Форматирование (единицы,
разделители, знаки, локализация) — это логика отображения и она принадлежит
компоненту: данные передаются числами и объектами `Date`, а не готовыми
строками.

## Макет страницы

```
┌──────────────────────────────────────────────────────────────┐
│  Header: только подпись (заголовок)                           │
├──────────────────────────────────────────────────────────────┤
│  Toolbar: период (слева)          ·  сегмент клиента (справа) │
├──────────────────────────────────────────────────────────────┤
│  Row 0: 6 × KPI-карточки                                       │
├───────────────────────────────┬──────────────────────────────┤
│  Row 1: Рейтинг менеджеров    │  Сравнение менеджеров         │
├───────────────────────────────┼──────────────────────────────┤
│  Row 2: Клиенты — Топ-10      │  Динамика клиентов            │
├───────────────────────────────┼──────────────────────────────┤
│  Row 3: Динамика во времени   │  Продажи по категориям        │
├───────────────────────────────┼──────────────────────────────┤
│  Row 4: Лучшие продукты       │  Последние продажи            │
├───────────────────────────────┼──────────────────────────────┤
│  Row 5: Возвраты              │  Отмены                       │
└───────────────────────────────┴──────────────────────────────┘
```

**Сетка.** 12 колонок, страница центрируется, ограничена по максимальной ширине.
Все ряды, кроме KPI и тулбара, — пары карточек равной ширины.

**Порядок рядов.** «Кто продаёт» (менеджеры) → «кому продаём» (клиенты) → «как
меняется» (динамика и структура) → «что продаём» (продукты и лента сделок) →
«что ушло» (потери). KPI отвечает на «как дела за период», поэтому идёт первым.

**Три типоразмера карточек.** Дашборд использует три высоты карточек:

| Типоразмер | Где используется | Назначение |
|---|---|---|
| **Компактная** | KPI-карточки (ряд 0) | Одно число + Δ + sparkline; высота минимальна |
| **Стандартная** | Ряды 1–4 (8 карточек) | Полноценные блоки со списками и графиками |
| **Уменьшенная** | Возвраты и Отмены (ряд 5) | Сжатый формат: число, доля, sparkline, список |

Высота карточки **задаётся типоразмером, а не содержимым**: данные, skeleton,
ошибка и пустое состояние занимают одинаковый объём, поэтому загрузка и смена
периода не двигают соседние блоки. Обе карточки пары всегда одной высоты.

Всё, что не помещается в карточку, скроллится **внутри** неё — колесо внутри блока
не прокручивает страницу. Внизу скроллируемых списков — затухание (fade) как
маркер продолжения. Контролов «развернуть блок» нет: они меняли бы высоту сетки.

## Сквозные правила отображения чисел

Применяются во всех блоках, чтобы не дублировать в каждом описании.

| Ситуация | Результат | Примечание |
|---|---|---|
| Метрика неопределена (пустой знаменатель) | `—` | Не `0`, не `0%` |
| Реальный ноль | `0` / `0 ₽` | Отличается от `—` |
| Отрицательное значение | `−x` (U+2212, не дефис) | |
| Δ метрики-доли (маржинальность, доли возвратов/отмен) | в **процентных пунктах** (п.п.) | |
| Δ остальных метрик | в **%** | |
| Цвет Δ | по **семантике** метрики, не направлению числа | Для «плохих» метрик (возвраты, отмены) рост — красный, падение — зелёное |
| Недостаточно данных для Δ | `—` | Базовый период пуст или данных недостаточно |

### Формат данных и тип Delta

Данные приходят **сырыми числами**, а не предформатированными строками: метрика
— `number`, Δ — структура `Delta | null`, ряд sparkline — массив
`{value, date}` с числом и объектом `Date`. Компонент сам приводит значение к
виду для показа (разделители тысяч, запятая как десятичный разделитель,
единицы, локализация). Компонент не вычисляет метрики — только форматирует
готовые числа.

Δ передаётся структурой `Delta` и может отсутствовать:

```ts
type Delta = {
  value: number;              // всегда число; знак определяет направление
  unit: 'percent' | 'pp';     // '%' — относительная; 'п.п.' — дельта доли
};
```

Правила отображения `Delta`:

- `delta === null` → недостаточно данных для расчёта → показывается `—`;
- направление (стрелка `▲`/`▼`) берётся из **знака** `value` — отдельного поля
  направления нет;
- суффикс берётся из `unit`: `percent` → `%`, `pp` → `п.п.`;
- цвет выбирается по **семантике метрики** (конфиг блока), а не по направлению
  числа: для «плохих» метрик рост — красный, падение — зелёное;
- форматирование числа (запятая-разделитель, U+2212 для минуса) — на компоненте.

Пример: `{ value: 12.4, unit: 'percent' }` → `▲ +12,4%`;
`{ value: -0.4, unit: 'pp' }` → `▼ −0,4 п.п.`; `null` → `—`.

### Тип Dataset

Каждый датасет — собственный набор элементов, отсортированный по метрике.
Каждый элемент несёт один `contribution`, рассчитанный для метрики этого
датасета. Переключение выполняется на клиенте без перезапроса: все датасеты
приходят одновременно, карточка лишь выбирает активный.

```ts
type Dataset<T> = {
  name: string;       // подпись (метрика)
  items: T[];         // массив элементов, отсортированных по метрике
};
```

### Тип Contribution

Вклад элемента в результат периода — структура с тремя формами одного и того же
значения: крупное число, подпись и бар:

```ts
type Contribution = {
  valueAbsolute: number;       // крупное значение на карточке (сырое число)
  valueRelative: number;       // подпись вклада: 26,2 или 1,7 (сырое число)
  valueRelativeUnit: 'gp' | 'ac' | 'revenue' | 'units';  // метрика вклада — определяет формат и текст подписи
  valueNormalized: number;      // значение бара, 0–100 (готовое)
};
```

Правила отображения `valueRelative` + `valueRelativeUnit`:

- `'gp'` → доля от общей ВП, печатается `26,2% от ВП`;
- `'revenue'` → доля от общей выручки, печатается `17,6% от выручки`;
- `'units'` → доля от общего объёма, печатается `12,3% от объёма`;
- `'ac'` → кратность среднему чеку, печатается `1,7× к СЧ`.

Компонент форматирует числа (запятая-разделитель, `%` / `×`) и подставляет
текст подписи по `valueRelativeUnit`, как и у `Delta`. Бизнес-расчёт
выполняется извне.

Каждый датасет содержит элементы с одним `contribution` — рассчитанным для
метрики этого датасета. Переключение датасета выполняется на клиенте без
перезапроса данных.

### Цвета серий метрик

Цвет активной метрики задаётся **позицией её датасета** в переключателе карточки и
одинаков для всех карточек: **1-й датасет — синий, 2-й — зелёный, 3-й — оранжевый**.
Правило распространяется на бары и линии, управляемые датасетами: «Рейтинг
менеджеров», «Сравнение менеджеров», «Клиенты — Топ-10», «Динамика во времени»,
«Лучшие продукты». Цвета Δ (рост/падение) и палитра категорий — отдельные и этому
правилу не подчиняются.

## Header

Только заголовок приложения, без подзаголовка. Без контролов, без фона и
без нижней границы — он не конкурирует с контентом за внимание. Между header
и тулбаром есть отступ.

---

## Тулбар (глобальные фильтры)

Постоянный бар под header с нижней границей. **Sticky**: при скролле
прилипает к верхнему краю, чтобы переключить период или сегмент можно было
в любой момент без возврата наверх.

**Два независимых глобальных фильтра разнесены по краям бара**: левый край —
«когда», правый — «для кого».

### Период (слева)

- Сегментированный контрол пресетов: `Сегодня` · `7 дней` · `30 дней` ·
  `Этот месяц` · `Прошлый месяц`.
- Кнопка `Произвольный период` — отдельный контрол, визуально отделённый от
  пресетов (другой стиль или разделитель), всегда активный. Выбор дат переводит
  контрол в режим «произвольный» и снимает подсветку с пресетов.
- **Вторая строка под контролами** — подпись активного диапазона:
  `17 сент 2026 — 23 сент 2026 · 7 дней` (даты основным цветом, длительность —
  вторичным).

**Контракт данных:** активный пресет либо `from`/`to`; вычисленная длительность
периода.
**Поведение:** смена периода запускает фоновую перезагрузку всех блоков
(stale-while-revalidate); диапазон сохраняется в URL (`?from=...&to=...`).
**Граничные случаи:** невалидный диапазон невозможно выбрать в контроле —
пикер не даёт завершить выбор.

### Сегмент клиента (справа)

- Сегментированный контрол `Крупный бизнес` · `Средний бизнес` · `Малый бизнес`
  (значения enum — `domain.md`, «Сегменты клиентов»).
- **Выбран либо один сегмент, либо ни одного.** Ни одного = все клиенты.
  Повторный клик по активной кнопке снимает выбор.
- **Ширина кнопки не меняется при переключении**: активное состояние отличается
  только фоном и цветом текста, без жирности и без дополнительных знаков.

**Контракт данных:** список доступных сегментов; активный сегмент или его
отсутствие.
**Поведение:** фильтр применяется ко всем блокам вместе с периодом; состояние
сохраняется в URL.
**Граничные случаи:** если в выбранном сегменте за период нет данных — блоки
показывают свои пустые состояния, а не скрываются.

## 1. KPI-карточки

**Назначение.** Мгновенный ответ на вопрос «как дела за период».

**Состав — 6 карточек в ряд:** Выручка · Валовая прибыль · Маржинальность ·
Количество продаж · Средний чек · Лучший менеджер. Типоразмер — компактный.

**Анатомия карточки:**
- подпись метрики (мелкий капс, приглушённый цвет);
- главное число — крупная типографика;
- Δ-бейдж к предыдущему сопоставимому периоду: `▲ +12,4%` / `▼ −3,1%`;
- sparkline дневной динамики за период, прижат к нижнему краю карточки
  (для числовых метрик).

**Карточка «Лучший менеджер»** показывает аватар (если нет — инициалы), имя,
ВП и число продаж лидера, ниже — Δ ВП. Sparkline по выручке конкретного
менеджера за период.

**Контракт данных:**

**KPI-карточки:**

| Поле | Описание |
|---|---|
| `title` | Подпись метрики |
| `value` | Значение метрики за период (`number`) |
| `delta` | Δ к предыдущему периоду (`Delta | null`) |
| `series` | Ряд для sparkline: массив `{value, date}` — `value` (число), `date` (объект Date) |

Карточка форматирует `value` и `delta` по правилам отображения (см. «Формат
данных и тип Delta») — бизнес-расчёт выполняется извне.

**Контракт данных (карточка «Лучший менеджер»):**

| Поле | Описание |
|---|---|
| `title` | Подпись карточки |
| `name` | Имя менеджера |
| `avatar` | Аватар (если нет — показываются инициалы) |
| `initials` | Инициалы (фолбэк для аватара) |
| `gp` | Валовая прибыль (`number`) |
| `salesCount` | Число продаж (`number`) |
| `delta` | Δ ВП к предыдущему периоду (`Delta | null`) |
| `series` | Ряд выручки менеджера для sparkline: массив `{value, date}` — `value` (число), `date` (объект Date) |

**Граничные случаи:** `—` = неопределено (пустой знаменатель), `0`/`0 ₽` =
реальный ноль. Пустой период — `—` и подпись «нет продаж за период». Loading —
skeleton; ошибка — иконка и кнопка «Повторить».

## 2. Рейтинг менеджеров

**Назначение.** Кто приносит результат и какую долю общего результата даёт каждый.

**Состав.** Сегментированный переключатель метрики:
`Валовая прибыль` | `Средний чек`. Ранжированный список, скроллится внутри
карточки. Типоразмер — стандартный.

**Строка (уровень 1):** позиция (топ-3 акцентированы) · аватар с инициалами · имя
· трек с баром · крупное значение активной метрики · вклад.
Под именем — контекст: Команда/кол-во продаж.

**Строка (уровень 2) — сетка метрик:** Выручка, Валовая прибыль, Маржинальность,
Средний чек, Отмены. Каждое поле со своей Δ к предыдущему периоду.

**Поведение:**
- **Бар** — `valueNormalized` из `contribution` активного датасета, приходит
  готовым. Длина бара — визуальный масштаб значения, а не доля.
- **Вклад** — `contribution` из активного датасета: доля от общей ВП периода
  либо кратность среднему чеку. Карточка не вычисляет его.
- **Доля отмен** — приходит как `cancelRate`: `null` при недостаточной выборке,
  конкретное значение иначе. **Возвраты в рейтинг не попадают.**
- При переключении метрики меняются бар, крупное число и вклад — вёрстка строк
  стоит на месте.

**Контракт данных:**

| Поле | Описание |
|---|---|
| `datasets[]` | Два датасета: `Валовая прибыль` (items — менеджеры, отсортированные по ВП) и `Средний чек` (items — менеджеры, отсортированные по СЧ) |
| `datasets[].items[].name` | Имя менеджера |
| `datasets[].items[].avatar` | Аватар (если нет — показываются инициалы) |
| `datasets[].items[].initials` | Инициалы (фолбэк для аватара) |
| `datasets[].items[].team` | Команда (для контекста под именем) |
| `datasets[].items[].salesCount` | Число продаж (`number`) |
| `datasets[].items[].revenue` | Выручка (`number`) |
| `datasets[].items[].revenueDelta` | Δ выручки (`Delta | null`) |
| `datasets[].items[].gp` | Валовая прибыль (`number`) |
| `datasets[].items[].gpDelta` | Δ ВП (`Delta | null`) |
| `datasets[].items[].ac` | Средний чек (`number`) |
| `datasets[].items[].acDelta` | Δ среднего чека (`Delta | null`) |
| `datasets[].items[].margin` | Маржинальность (`number`) |
| `datasets[].items[].marginDelta` | Δ маржинальности (`Delta | null`) |
| `datasets[].items[].cancelRate` | Доля отмен (`number | null`) |
| `datasets[].items[].cancelRateDelta` | Δ доли отмен (`Delta | null`) |
| `datasets[].items[].contribution` | Вклад менеджера по метрике датасета (`Contribution`) |

**Граничные случаи:** менеджер без продаж — в списке с нулями и приглушённым
стилем (не скрывается). Равные значения — детерминированный порядок
(`domain.md`), позиции не «прыгают». Skeleton / ошибка / пустой период — как в
KPI.

## 3. Сравнение менеджеров

**Назначение.** Как соотносятся два измерения результата у топ-менеджеров.

**Состав.** Свой переключатель метрики (`Валовая прибыль` | `Средний чек`) — набор
тот же, что и у «Рейтинга менеджеров», метрика выводится по одной. Горизонтальный
bar-chart: по одному столбцу на менеджера. **Оси развёрнуты** — менеджеры по Y,
значения по X: длинные имена и значения читаются без поворота подписей.
Типоразмер — стандартный.

**Ростер.** Топ-10 менеджеров **по активной метрике** (по убыванию) — при
переключении датасетов меняются и состав, и порядок строк. Каждая метрика выводится
на собственной шкале; единицы измерения подписаны на оси X и в tooltip.

**Контракт данных:**

| Поле | Описание |
|---|---|
| `datasets[]` | Два датасета: `Валовая прибыль` (items — топ-10 по ВП) и `Средний чек` (items — топ-10 по СЧ) |
| `datasets[].items[].name` | Имя менеджера |
| `datasets[].items[].value` | Значение метрики датасета (`number`) |
| `datasets[].items[].delta` | Δ метрики датасета (`Delta | null`) |

**Поведение:** справа от каждого столбца — Δ соответствующей метрики (цвет по
семантике); hover — tooltip с точными значениями.
**Граничные случаи:** N ограничен десятью — при большем числе группы столбцов
сливаются. Отмены и возвраты в блок не добавляются (их разрезы живут в своих
блоках). Пустой период / ошибка / skeleton — как в KPI.

## 4. Клиенты — Топ-10

**Назначение.** Кто из клиентов даёт больше всего за период.

**Состав.** Переключатель метрики: `Валовая прибыль` | `Средний чек`.
Ранжированный список. Типоразмер — стандартный.

**Строка (уровень 1):** номер · маркер клиента · имя · трек с баром · значение · вклад.
Под именем — `клиент с 2023 · 18 заказов`.

**Строка (уровень 2) — сетка метрик:** Выручка, Валовая прибыль, Маржинальность,
Средний чек, Возвраты, Отмены — каждое поле со своей Δ.

**Поведение.** Вклад приходит готовым значением для каждого клиента; карточка не
вычисляет его. Доли возвратов и отмен приходят как `refundRate`/`cancelRate`:
`null` при недостаточной выборке, конкретное значение иначе.
**Контракт данных:**

| Поле | Описание |
|---|---|

## 10. Потери за период: Возвраты и Отмены

**Назначение.** Две группы того, что не вошло в выручку: что вернули и что не
состоялось. Отвечают на три вопроса — сколько это в деньгах, как ведёт себя по
дням, и где именно утечка.

**Главное правило.** Возвраты и отмены **не сводятся в общий итог**. Формулировки
«всего потерь», «сумма проблем», один общий бар или одна общая Δ запрещены: у
групп разные виновники, причины и действия (`domain.md`). Это **два независимых
блока** (не одна карточка с двумя колонками), каждый в своей карточке
уменьшенного типоразмера.

**Разрез жёстко привязан и не переключается пользователем:** возвраты — только
товары, отмены — только менеджеры.

**Состав каждой группы:**
- крупное число — сумма потерь группы;
- рядом — доля группы (`Refund Rate` / `Cancellation Rate`) со своей Δ в п.п.;
- sparkline по дням активного периода;
- список топа: объект + подпись · бар · сумма · доля от суммы группы.

**Поведение.**
- Список — любой объект с хотя бы одной потерей; **порога доли как условия
  входа нет** (если все ниже порога внимания — это хороший сигнал, он обязан
  быть виден строками с числами, а не пустым списком).
- Сортировка по сумме по убыванию; доля от итога группы — монотонный множитель
  суммы, поэтому отдельного переключателя ранжирования нет.
- **Акцента в списке нет:** строка печатает долю от утечки группы, а порог
  внимания оценивается по собственной доле объекта — это разные числа, и два
  процента рядом читатель спутает.
- Хвост «Остальные N» печатается без бара, доля — с ним; сумма долей строк и
  хвоста даёт 100% группы. Хвост появляется только когда за топом остались
  объекты.
- Tooltip на строке: обе величины и база доли.

**Контракт данных:**

| Поле | Описание |
|---|---|
| `refund.value` | Сумма потерь группы за период (`number`) |
| `refund.rate` | Доля группы (`number`) |
| `refund.rateDelta` | Δ доли (`Delta | null`) |
| `refund.series` | Ряд для sparkline: массив `{value, date}` — `value` (`number`), `date` (`Date`) |
| `refund.top[]` | Топ объектов: `name`, `category`, `valueAbsolute` (`number`), `valueRelative` (`number`), `valueNormalized` (0–100) |
| `refund.tail` | Хвост «Остальные N»: `valueAbsolute` (`number`), `valueRelative` (`number`) — или `null` |

**Граничные случаи:** нет отмен/возвратов — крупное число `0 ₽` (реальный
ноль, не `—`) и подпись «Отмен нет» / «Возвратов нет». Доля неопределена
(пустой знаменатель) — `—`. Объектов меньше десяти — показывается сколько
есть. Продаж нет, отмены есть — группа «Отмены» заполнена, «Возвраты» в
`0`/`—`.

## Глобальные состояния

Дашборд обязан корректно отображать все следующие состояния — в любом сочетании
на разных карточках одновременно. Вечного spinner'а, белого экрана и
внезапно пустого блока быть не должно.

### 1. Initial loading

Полная загрузка при первом открытии. Все карточки показывают **skeleton** по
форме контента — не спиннер на весь экран и не абстрактные блоки: skeleton
повторяет структуру реального содержимого (строки рейтинга, строки продуктов,
sparkline-зоны, зона донат-чарта и т.д.), чтобы пользователь видел, что
загружается.

### 2. Loading при смене периода

При смене периода (или сегмента) в тулбаре: **старый контент остаётся
видимым** — карточки не исчезают, не «моргнут» белым. Вместо этого поверх
дашборда появляется **toast-уведомление** вверху экрана: иконка загрузки +
подпись `Обновление данных…`. Когда новые
данные придут, контент плавно обновится.

### 3. Ошибка API

Два варианта:

- **3A — Initial loading не завершён**: skeleton всё ещё виден + toast-уведомление
  сверху: `Не удалось загрузить данные` (красный фон) с кнопкой `Обновить`.
- **3B — Данные уже были загружены ранее**: показывается **последнее
  загруженное состояние** (старые данные), + toast-уведомление: `Не удалось
  обновить данные. Показаны данные за предыдущий период` с кнопкой `Обновить`.

### 4. Пустой период без продаж

Когда за выбранный период нет оплаченных продаж:

- **KPI-карточки** показывают `—` с подписью `данных нет`;
- **Блоки, считающие оплаченные продажи** (KPI, Рейтинг, Сравнение, Клиенты,
  Динамика клиентов, Динамика во времени, Категории, Продукты, Последние
  продажи) — показывают осмысленную заглушку: иконка, заголовок
  `За выбранный период данных нет`, подпись `Попробуйте изменить период или
  сегмент`;
- **Блоки «Потери»** (Возвраты, Отмены) — **не перекрываются** общим
  «нет данных»: они показывают свои собственные заглушки `Возвратов нет` /
  `Отмен нет` с подписью `За выбранный период возвратов/отмен не
  зафиксировано`.

### 5. Нет данных по отдельному блоку

Когда данные есть по некоторым блокам, но отсутствуют по другим:

- **Блоки с данными** — показывают заполненный контент;
- **Блоки без данных** — показывают ту же заглушку, что и пустой период
  (иконка, `За выбранный период данных нет`, подсказка).

Каждая карточка работает **независимо**: отсутствие данных в одной не влияет
на отображение других.
