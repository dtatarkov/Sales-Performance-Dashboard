# Sales Performance Dashboard — спецификация UI

Desktop-приложение, целевой viewport **1440×900**. Mobile-версия не требуется.
Страница одна — сводный дашборд аналитики продаж менеджеров.

## Макет страницы

```
┌──────────────────────────────────────────────────────────────┐
│  Header: заголовок + переключатель периода [пресет ▼][from→to]  │
├──────────────────────────────────────────────────────────────┤
│  Row 1: 6 × KPI-карточки                                      │
├───────────────────────────────┬──────────────────────────────┤
│  Row 2: Динамика (график)     │  Рейтинг менеджеров          │
├───────────────────────────────┼──────────────────────────────┤
│  Row 3: Категории (donut)     │  Сравнение менеджеров (bar)  │
├───────────────────────────────┴──────────────────────────────┤
│  Row 4: Лучшие продукты (table)                               │
├──────────────────────────────────────────────────────────────┤
│  Row 5: Последние продажи (table)                             │
└──────────────────────────────────────────────────────────────┘
```

Сетка: 12-колоночная, gap 16–24px. Карточки — единый контейнер с заголовком,
тулбаром (переключатели/фильтры) и областью контента.

---

## 1. Переключатель периода (Period Selector)

**Назначение.** Задаёт временное окно для всех блоков страницы. Единственный
глобальный фильтр — состояние поднимается в стор/URL и влияет на все запросы.

**Состав.**
- Сегментированный control с пресетами: `Сегодня` · `7 дней` · `30 дней` ·
  `Этот месяц` · `Прошлый месяц`.
- Кнопка/поп-овер `Произвольный период` — два поля даты **from → to**
  (date-range picker, инлайн-валидация: from ≤ to, не позже сегодняшней даты).
- Рядом — читаемая подпись активного диапазона: `14 сент 2026 — 23 сент 2026`,
  и вторичная строка с длительностью (`10 дней`).

**Поведение.**
- Смена периода мгновенно запускает фоновую перезагрузку всех блоков (stale-while-revalidate).
- Активный пресет подсвечен; выбор дат из календаря переключает control в режим «произвольный».
- Диапазон сохраняется в URL (`?from=...&to=...`) — перезагрузка/шаринг ссылки восстановляет вид.

**Состояния.** При невалидном диапазоне — инлайн-ошибка, запрос не отправляется.

---

## 2. KPI-карточки (KPI Cards)

**Назначение.** Мгновенный ответ на вопрос «как дела за период».

**Состав — 6 карточек в ряд:**
1. **Выручка** (Revenue)
2. **Валовая прибыль** (Gross Profit)
3. **Маржинальность** (Margin)
4. **Количество продаж** (Sales count)
5. **Средний чек** (Average Check)
6. **Лучший менеджер** (Top Manager)

**Анатомия карточки.**
- Подпись метрики (мелый капс, приглушённый цвет).
- Главное число — крупная типографика, **animated counter** (счёт от 0 до значения).
- **Бейж сравнения** с предыдущим сопоставимым периодом: `▲ +12,4%` / `▼ −3,1%`.
  Зелёный для роста «хороших» метрик, красный для падения; для Margin/прибыли
  знак интерпретируется по направлению метрики. Подсказка в tooltip:
  `к периоду 24 авг — 02 сент`.
- **Sparkline** (мини-график дневной динамики за активный период) — для
  числовых метрик.
- В карточке «Лучший менеджер» вместо sparkline — аватар/инициалы + имя +
  value-подпись (`Gross Profit: 1,24 млн ₽`).

**Форматирование.** Деньги — компактно с единицами (`1,2 млн ₽` / `845 тыс ₽`),
полное значение в tooltip. Проценты — один знак после запятой.

**Состояния.** Loading — skeleton карточки. Ошибка — карточка с иконкой и
кнопкой «Повторить». Пустой период — `—` и подпись «нет продаж за период».

## 3. Динамика во времени (Trend Chart)

**Назначение.** Как метрики вели себя внутри периода — рост, провалы, сезонность.

**Состав.**
- Area/line-чарт по дням (или по неделям при длинном периоде).
- Переключатель метрики: `Revenue` | `Gross Profit` | `Количество продаж`
  (сегмент-контрол в тулбаре карточки).
- Ось X — даты, ось Y — значения выбранной метрики.
- Hover-tooltip: дата + значение; вертикальная направляющая.
- Опционально — тонкая линия предыдущего периода для визуального сравнения.

**Поведение.** Плавный переход (morph) кривой при смене метрики и периода.

**Состояния.** Skeleton при загрузке. Одна точка (период = сегодня) — чертится
корректно без растягивания. Пустой период — заглушка «нет данных».

---

## 4. Рейтинг менеджеров (Manager Leaderboard)

**Назначение.** Центральный элемент — кто приносит результат и в каких метриках.

**Состав.**
- Сегментированный переключатель режима ранжирования:
  **`Gross Profit`** | **`Average Check`** (минимум два режима).
- Таблица/список строк менеджеров, отсортированных по выбранной метрике.

**Анатомия строки рейтинга (по секции 6):**
| Колонка | Содержание |
|---|---|
| Позиция | `#1, #2, …` — крупно; топ-3 акцентированы (медаль/цвет) |
| Менеджер | Аватар или инициалы + имя + команда/должность (подпись) |
| Кол-во продаж | Целое число |
| Выручка | Деньги, компактно |
| Валовая прибыль | Деньги; **в режиме сортировки по GP** — бар-в-ячейке (доля от максимума) |
| Средний чек | Деньги; **в режиме AC** — акцентирован как метрика-сортировка |
| Маржинальность | % + мини-цветовой индикатор (низкая/средняя/высокая) |
| Δ к пред. периоду | `▲/▼ +x%` по метрике сортировки |

**Поведение.**
- **Плавное перестроение строк** при смене режима ранжирования (FLIP-анимация).
- Активная сортировочная колонка подсвечена.
- Строки с равными значениями метрики ранжируются стабильно (детерминированный
  тай-брейк — см. `terms.md`), без «прыжков» при перезагрузке.
- Клик по строке — опционально фильтрует другие блоки по менеджеру (инициатива).

**Состояния.** Менеджер без продаж за период — включается в рейтинг с нулями и
приглушённым стилем (не скрывается молча, иначе «исчезают» люди). Skeleton /
ошибка / пустой период — как в KPI.

## 5. Категории и продукты (Categories & Top Products)

Разнесён на два блока.

### 5a. Продажи по категориям (Category Breakdown)
**Назначение.** Структура выручки/прибыли по товарным категориям.
**Состав.**
- Donut-чарт **доли категорий** по переключателю `Revenue` | `Gross Profit`.
- Рядом/под чартом — легенда-таблица: категория, сумма, валовая прибыль,
  маржинальность %, кол-во продаж.
- Hover сегмента подсвечивает строку легенды и наоборот.

### 5b. Лучшие продукты (Top Products)
**Назначение.** Что именно продаётся — товары-лидеры.
**Состав.** Таблица топ-N (N≈10) продуктов:
- Название продукта + категория (подпись).
- Выручка, валовая прибыль, кол-во продаж, маржинальность.
- Сортировка по выручке (или переключаемо); индикатор доли от общей выручки
  (горизонтальный бар в ячейке).

**Состояния.** Блок с одним товаром в категории — donut рисуется корректно.
Отсутствие данных — заглушка блока, а не пустой контейнер.

---

## 6. Сравнение менеджеров (Manager Comparison) — доп. блок

**Назначение.** Многомерное сравнение, а не только линейный рейтинг.
**Состав.** Сгруппированный bar chart: по каждому менеджеру пара столбцов
(Revenue / Gross Profit) либо переключатель метрики. Топ-N по активной метрике,
чтобы не захламлять. Hover-tooltip с точными значениями.

---

## 7. Распределение и маржа (Distribution) — доп. блок

**Назначение.** Понять «много мелких или мало крупных» — форма распределения.
**Состав** (выбрать 1–2, по полезности):
- **Гистограмма** распределения сумм продаж по корзинам (сегменты чека).
- **Scatter plot**: средний чек (X) × маржинальность (Y), точка = менеджер,
  размер = кол-во продаж. Визуально отделяет «дорого и маржинально» от «массово и дёшево».

---

## 8. Последние продажи (Recent Sales)

**Назначение.** Живая лента сделок, доказательство актуальности данных.
**Состав.** Таблица последних M продаж (период не влияет — это глобальная лента,
либо влияет — решить и зафиксировать в README):
| Колонка | Содержание |
|---|---|
| Дата | ДД.MM, HH:mm |
| Менеджер | Имя (инициалы опц.) |
| Клиент | Имя клиента + компания |
| Товары | Перечень позиций, свёрнутый (`3 товара` + expand / tooltip) |
| Статус | Цветной бейдж: `Paid` (зелёный) · `Cancelled` (серый) · `Refunded` (оранжевый/красный) |
| Сумма | Выручка по продаже |
| Валовая прибыль | Деньги |

**Поведение.** Плавные transition при смене данных; hover-подсветка строки;
скролл внутри контейнера фиксированной высоты.

**Состояния.** Статусы Cancelled/Refunded визуально не должны «ломать» суммы —
подпись в tooltip, как они учтены (см. `terms.md`).

---

## 9. Глобальные состояния интерфейса (секция 10)

Каждый блок обязан корректно отрисовать:
- **Initial loading** — skeleton по форме контента (не спиннер на весь экран).
- **Loading при смене периода** — старый контент остаётся, поверх лёгкий
  индикатор (shimmer/прогресс-бар), без «белой вспышки».
- **Ошибка API** — в карточке: иконка + текст + «Повторить»; не ронять всю страницу.
- **Пустой период без продаж** — осмысленная заглушка «За выбранный период
  продаж нет» + подсказка сменить период.
- **Нет данных по отдельному блоку** — блок объясняет причину, а не показывается пустым.

> Критерий приёмки: вечного spinner'а, белого экрана и внезапно пустого блока
> быть не должно.
